Polecenia · użytkownicy i grupy


    

  • sudo useradd -m anna: nowy użytkownik z katalogiem domowym; hasło: sudo passwd anna.
    • 

  • sudo adduser anna: to samo interaktywnie (pyta o hasło i dane).
    • 

  • sudo groupadd studenci: nowa grupa.
    • 

  • sudo usermod -aG studenci anna: dopisanie do grupy. Bez -a lista grup zostaje zastąpiona.
    • 

  • sudo gpasswd -a anna studenci albo sudo adduser anna studenci: to samo inaczej.
    • 

  • sudo gpasswd -d anna studenci: usunięcie z grupy.
    • 



Sprawdzenie: id anna, groups anna, getent group studenci.

⫽

Commands · users and groups


    

  • sudo useradd -m anna: a new user with a home directory; password: sudo passwd anna.
    • 

  • sudo adduser anna: the same, interactively (asks for the password and details).
    • 

  • sudo groupadd studenci: a new group.
    • 

  • sudo usermod -aG studenci anna: add to a group. Without -a the group list is replaced.
    • 

  • sudo gpasswd -a anna studenci or sudo adduser anna studenci: the same in another way.
    • 

  • sudo gpasswd -d anna studenci: remove from a group.
    • 



Check: id anna, groups anna, getent group studenci.

Wzory · prawa rwx


W ls -l po literze typu (d katalog, - plik) stoją trzy trójki: właściciel (u), grupa (g), inni (o). Cyfry: r = 4, w = 2, x = 1.


    

  • rwx = 7, rw- = 6, r-x = 5, r-- = 4, --- = 0.
    • 

  • chmod 750 kat to rwxr-x---; chmod 640 plik to rw-r-----.
    • 

  • chmod g=r kat: grupa ma tylko odczyt. g+r dodaje, g-w zabiera.
    • 

  • Katalog: r wypisanie nazw, w tworzenie i usuwanie plików, x wejście (cd).
    • 

  • sudo chgrp studenci kat, sudo chown anna:studenci kat: zmiana grupy i właściciela.
    • 


⫽

Formulas · rwx permissions


In ls -l, after the type letter (d directory, - file) come three triples: owner (u), group (g), others (o). Digits: r = 4, w = 2, x = 1.


    

  • rwx = 7, rw- = 6, r-x = 5, r-- = 4, --- = 0.
    • 

  • chmod 750 dir is rwxr-x---; chmod 640 file is rw-r-----.
    • 

  • chmod g=r dir: the group has only read. g+r adds, g-w removes.
    • 

  • Directory: r lists names, w creates and deletes files, x lets you enter (cd).
    • 

  • sudo chgrp studenci dir, sudo chown anna:studenci dir: change the group and the owner.
    •

Przepis · ACL


    

  • setfacl -m u:anna:rwx kat: prawa dla użytkownika.
    • 

  • setfacl -m g:studenci:rw- kat: prawa dla grupy.
    • 

  • setfacl -d -m u:anna:rwx kat: ACL domyślne, dziedziczone przez nowe pliki w katalogu (to samo: -m d:u:anna:rwx).
    • 

  • setfacl -d -m o::r kat: domyślnie inni tylko czytają.
    • 

  • setfacl -m m::r-x plik: maska.
    • 

  • setfacl -x u:anna plik usuwa wpis, -b całe ACL, -k tylko domyślne.
    • 



Sprawdzenie: getfacl plik. W ls -l ACL zdradza znak + po prawach.

⫽

Recipe · ACL


    

  • setfacl -m u:anna:rwx dir: permissions for a user.
    • 

  • setfacl -m g:studenci:rw- dir: permissions for a group.
    • 

  • setfacl -d -m u:anna:rwx dir: the default ACL, inherited by new files in the directory (also: -m d:u:anna:rwx).
    • 

  • setfacl -d -m o::r dir: by default others only read.
    • 

  • setfacl -m m::r-x file: the mask.
    • 

  • setfacl -x u:anna file removes an entry, -b the whole ACL, -k only the default one.
    • 



Check: getfacl file. In ls -l an ACL shows as a + after the permissions.

Uwaga · maska ACL


Maska ogranicza nazwanych użytkowników, nazwane grupy i grupę właścicielską (nie właściciela i nie innych). Efektywne prawa to część wspólna wpisu i maski: rwx i maska r-x dają r-x; getfacl dopisuje wtedy #effective:r-x.


Każde setfacl -m przelicza maskę od nowa, więc maskę ustawiamy na końcu (albo z opcją -n). Przy ACL środkowa trójka w ls -l pokazuje maskę.

⫽

Note · the ACL mask


The mask limits named users, named groups and the owning group (not the owner and not others). The effective permissions are the intersection of the entry and the mask: rwx with the mask r-x gives r-x; getfacl then adds #effective:r-x.


Every setfacl -m recalculates the mask, so set the mask last (or use -n). With an ACL the middle triple in ls -l shows the mask.

Wzory · grep na miasta.txt


    

  • grep '^G' miasta.txt: zaczynające się na G.
    • 

  • grep -E '^.{6}$' miasta.txt albo grep '^......$' miasta.txt: dokładnie 6 znaków.
    • 

  • grep '^[KL]' miasta.txt albo grep -E '^(K|L)' miasta.txt: na K lub L.
    • 

  • grep 'ów$' miasta.txt: kończące się na -ów.
    • 

  • grep -v '^S' miasta.txt: nie zaczynające się na S (Ś to inna litera).
    • 



^ początek linii, $ koniec, . dowolny znak, * zero lub więcej razy, [abc] jeden z listy, [^abc] żaden z listy. Opcje: -v odwraca, -c liczy, -i ignoruje wielkość liter, -n numeruje, -E włącza {n}, |, +, ?. Wzorzec piszemy w apostrofach.

⫽

Formulas · grep on miasta.txt


    

  • grep '^G' miasta.txt: starting with G.
    • 

  • grep -E '^.{6}$' miasta.txt or grep '^......$' miasta.txt: exactly 6 characters.
    • 

  • grep '^[KL]' miasta.txt or grep -E '^(K|L)' miasta.txt: starting with K or L.
    • 

  • grep 'ów$' miasta.txt: ending in -ów.
    • 

  • grep -v '^S' miasta.txt: not starting with S (Ś is a different letter).
    • 



^ start of line, $ end, . any character, * zero or more times, [abc] one from the list, [^abc] none from the list. Options: -v inverts, -c counts, -i ignores case, -n numbers lines, -E enables {n}, |, +, ?. Put the pattern in single quotes.

Przepis · statyczny adres IP


Plik /etc/netplan/01-netcfg.yaml (wcięcia spacjami):


network:
  version: 2
  ethernets:
    enp0s3:
      dhcp4: false
      addresses:
        - 193.107.32.22/24
      routes:
        - to: default
          via: 193.107.32.1
      nameservers:
        addresses: [8.8.8.8]


Potem sudo netplan apply, sprawdzenie: ip a i ip route. Na Ubuntu Desktop to samo da się ustawić przez nmcli albo w ustawieniach sieci. Pakiet z internetu (np. openssh-server) instalujemy, zanim karta dostanie adres bez dostępu do sieci.

⫽

Recipe · static IP address


The file /etc/netplan/01-netcfg.yaml (indent with spaces):


network:
  version: 2
  ethernets:
    enp0s3:
      dhcp4: false
      addresses:
        - 193.107.32.22/24
      routes:
        - to: default
          via: 193.107.32.1
      nameservers:
        addresses: [8.8.8.8]


Then sudo netplan apply; check with ip a and ip route. On Ubuntu Desktop the same can be set with nmcli or in the network settings. Install packages from the internet (e.g. openssh-server) before the card gets an address without network access.

Przepis · serwer SSH


    

  1. sudo apt update i sudo apt install openssh-server; stan: systemctl status ssh.
    2. 

  2. Port: w /etc/ssh/sshd_config wpisujemy Port 997. W nowszym Ubuntu działa też gniazdo ssh.socket, a klient może mieć port w /etc/ssh/ssh_config. Potem sudo systemctl daemon-reload, sudo systemctl restart ssh.socket, sudo systemctl restart ssh. Sprawdzenie: sudo ss -tlnp | grep 997.
    3. 

  3. Zapora na serwerze: sudo ufw allow 997/tcp (albo tylko ze stacji: sudo ufw allow from 193.107.32.22 to any port 997 proto tcp), potem sudo ufw enable. Na stacji roboczej: sudo ufw allow out 997/tcp. Stan: sudo ufw status.
    4. 

  4. Klucze, na stacji roboczej: ssh-keygen -t ed25519, ssh-copy-id -p 997 user@193.107.32.1.
    5. 

  5. Dopiero teraz na serwerze w sshd_config: PasswordAuthentication no, potem sudo systemctl restart ssh. Test: ssh -p 997 user@193.107.32.1 loguje bez hasła.
    6. 


⫽

Recipe · SSH server


    

  1. sudo apt update and sudo apt install openssh-server; status: systemctl status ssh.
    2. 

  2. Port: write Port 997 in /etc/ssh/sshd_config. Newer Ubuntu also uses the ssh.socket unit, and the client can keep the port in /etc/ssh/ssh_config. Then sudo systemctl daemon-reload, sudo systemctl restart ssh.socket, sudo systemctl restart ssh. Check: sudo ss -tlnp | grep 997.
    3. 

  3. Firewall on the server: sudo ufw allow 997/tcp (or only from the workstation: sudo ufw allow from 193.107.32.22 to any port 997 proto tcp), then sudo ufw enable. On the workstation: sudo ufw allow out 997/tcp. Status: sudo ufw status.
    4. 

  4. Keys, on the workstation: ssh-keygen -t ed25519, ssh-copy-id -p 997 user@193.107.32.1.
    5. 

  5. Only now, on the server, in sshd_config: PasswordAuthentication no, then sudo systemctl restart ssh. Test: ssh -p 997 user@193.107.32.1 logs in without a password.
    6.
